# 이미지 아카이브 사이트 인수인계

다른 컴퓨터에서 이 사이트 작업을 이어 가기 위한 문서다. 사이트 설계 규칙은 [design-spec.md](design-spec.md), 이미지 이용 주의사항은 [image-usage-cautions.md](image-usage-cautions.md), 이미지 수집처는 [image-sources.md](image-sources.md)에 있다.

## 1. 현재 상태 (2026-11-01 기준)

- **공개 주소:** https://doridu.com/ (`www` 와 옛 `2wdoridu.github.io/archive/` 는 여기로 넘어온다)
- **저장소:** https://github.com/2wdoridu/archive (공개, `main` 브랜치 루트에서 GitHub Pages 배포)
- **검색:** 완성 전까지 모든 쪽에 `noindex` 를 넣어 검색에 안 잡히게 막아 뒀다. 공개할 때 뺀다(6절 2-4).
- **단계:** 시안. 정적 HTML·CSS·JS로 만든 시안을 그대로 공개 중이다. 설계 문서의 최종 구조(Astro + 게시물 폴더)로는 아직 옮기지 않았다.
- **브랜드:** 이름 `2w_doridu Archive`, 계정 `@2w_doridu`, 메일 `hello@doridu.com`. 도메인 `doridu.com` 은 2026-11-01 구매해 2026-11-02 사이트에 연결했다.
- **숨긴 게시물(2026-11-01):** 커스텀 4개(붓꽃 들판, 밤의 붓꽃, 다시 비눗방울, 푸른 수확)와 도형 자리표시 작품 4개(정오의 면, 두 개의 돌, 창 연구, 반달). 굿즈까지 하면 26개 중 17개가 빠져 수집 원작 9개만 보인다. `data.js` 의 `HIDDEN` 에 id 를 넣어 거르는 방식이라 데이터는 그대로 있고, 목록에서 빼면 다시 보인다.
- **자리표시로 남아 있는 것:** 정보 페이지 소개 문구, 모든 구매 링크(`#`), 직접 만든 작품(Work)과 커스텀 작품 이미지, 굿즈 사진.
- **10-30(금)까지의 상태와 달라진 점:** 그때는 사이트 이름이 자리표시 `ARCHIVE`, 계정이 `@instagram_handle`, 정보 페이지 이름이 `작가 이름`이었다. 상단 바 오른쪽도 `@계정 · 카드 · 빵 스티커 · 정보` 네 줄이었다. 지금은 모두 아래 7절 '2026-11-01 브랜드·헤더' 항목대로 바뀌었다.

## 3. 다른 컴퓨터에서 시작하기

1. Git, Node.js, GitHub CLI, Claude Code를 설치한다.
2. GitHub CLI로 로그인한다: `gh auth login` 실행 후 브라우저에서 계정 `2wdoridu`으로 승인한다.
3. 저장소를 내려받는다: `gh repo clone 2wdoridu/archive`
4. 받은 `archive` 폴더에서 Claude Code를 연다. `CLAUDE.md`가 자동으로 읽힌다.
5. 로컬 확인: `node _tools/serve.mjs 4321` 실행 후 `http://localhost:4321` 접속.

커밋 작성자 이메일은 GitHub 비공개 주소를 쓴다.

```
git config user.name "2wdoridu"
git config user.email "40047261+2wdoridu@users.noreply.github.com"
```

## 4. 수정하고 배포하는 방법

1. 파일을 고치고 로컬 서버로 확인한다. PC는 1920px과 1536px(1920 모니터 + Windows 배율 125%), 휴대폰은 390px로 확인한다.
2. `index.html`, `detail.html`, `info.html`, `analysis-sample.html`에서 CSS·JS를 부르는 주소의 버전 표시(`?v=날짜-번호`)를 올린다. 현재 값은 `20261110-2`.
3. 커밋하고 `git push` 한다.
4. 1~2분 뒤 공개 주소에 반영된다. 브라우저가 예전 파일을 보여 주면 Ctrl+F5.

### 권리 확인 방법

- **메트로폴리탄:** 공식 API `https://collectionapi.metmuseum.org/public/collection/v1/objects/{번호}`의 `isPublicDomain`이 `true`면 CC0.
- **게티:** 작품 IIIF 매니페스트의 `rights`가 CC0인지 확인한다. 작품 데이터의 CC BY 4.0은 게티가 쓴 설명 글에만 해당한다.
- **시카고:** 공식 API `https://api.artic.edu/api/v1/artworks/{번호}`의 `is_public_domain`.
- **레이크스:** 작품 페이지 Copyright 항목이 Public Domain Mark인지, 이미지 다운로드가 열려 있는지.
- **공유마당:** 작품 페이지 이용조건이 `CC BY` 또는 `기증저작물 자유이용`인지 확인한다. `조건부이용`, `BY-NC`, `BY-ND`, `BY-SA`는 쓰지 않는다. 원본은 `/gongu/wrt/cmmn/wrtFileDownload.do?wrtSn={번호}&fileSn=1`로 받으며 gzip으로 압축되어 온다.
- 공통: 저작권은 제작 연도가 아니라 작가 사망 후 70년 기준이다. 작자 미상은 공표 후 70년.

**크게 보기(2026-11-10)**: 상세 카드 아래 동그라미 둘 중 왼쪽. 누르면 `body.is-zoom` 이 붙어 테두리 장식과 종이 판을 숨기고 장면을 화면에 맞춰 키운다. 장면이 3:4 로 그려지므로 비율은 그대로 두고 남는 곳은 어둡게 둔다. 다시 누르거나 Escape 로 돌아온다. 크게 본 동안에는 상단 바가 가려지므로 단추를 5초 뒤에 숨기지 않는다. 장면(`paradise.html`)은 창 크기가 바뀌면 그 크기에 맞춰 다시 그린다(먹선 굵기 `texel` 은 화면 크기와 무관하게 정해져 있어 건드리지 않는다).

**해 보고 되돌린 것**
- 그림자 지도를 두 프레임에 한 번만 갱신: 0.4ms 밖에 못 줄이면서 인물 옷과 짐칸 음영이 달라졌다. 이때 알게 된 것 — `shadowMap.autoUpdate` 를 끄지 않으면 `light.shadow.needsUpdate` 는 아무 일도 하지 않는다. 장면마다 `renderer.shadowMap.needsUpdate` 를 따로 켜 줘야 한다.
- 글꼴 CSS 를 첫 그림을 막지 않게(`media="print"`) 바꾸기: 느린 4G 에서 카드에 그림 뜨는 시각이 1,540ms → 2,140ms 로 나빠졌다.

### 배포
- NAS 하위 폴더 배포를 검토했으나 GitHub Pages로 정했다. NAS 웹 폴더 루트에는 다른 업무 시스템이 운영 중이라 절대 덮어쓰지 않는다.
- 커밋별 상세 변경은 `git log`로 확인한다.

## 8. 사업 구조 요약

```
손님: 사이트에서 [구매하기] → 네이버 스마트스토어에서 주문·결제
  → 주문 정보가 굿즈 제작·배송 대행사(POD SHOP)로 자동 전달
  → 판매자가 미리 등록한 디자인으로 제작 → 포장 → 손님에게 직접 택배
  → 구매확정 후 네이버가 판매자에게 정산
```
